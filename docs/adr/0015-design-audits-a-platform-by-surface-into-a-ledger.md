# ai-slop-design audits a whole platform by surface into a ledger, plans batches and publishes them, and only sweep edits

`sweep` works for a set of files someone means to fix. Pointed at a platform with dozens of routes and hundreds of components it breaks: every hit's JSON lands in the main agent's context, workers edit files before anyone has seen the whole platform, the judgment-only read and the screenshots happen in one context a platform does not fit in, verdicts live in a scratchpad and do not survive the session, and nothing turns findings into work a team can split. ai-slop-audit already has the shape that fixes this for code (ledger, inventory, audit, plan, publish), and it already reads this scanner's duplication hits, so both audits would report the same duplication.

The decisions, from a grilling session on 2026-11-16 (issue #15):

- **Three modes in ai-slop-design**, each in its own mode file next to CRAFT.md and SWEEP.md: `audit [path]` (read-only), `plan` and `publish [batches]`. ai-slop-design still never calls ai-slop-audit.
- **The unit is the surface**: a route or page plus the components only it reaches, so each hit is judged in the context of the page it renders on. Components reached by several surfaces form one `shared` unit, judged once, and every frontend file belongs to exactly one unit, so coverage `k/N surfaces` means what it says. Files no static read can place (auto-imported components, config) go to `shared` as `unreached` rather than out of the count.
- **Surfaces come from framework conventions** (Next.js, Nuxt, SvelteKit, Astro, react-router), read from `package.json`, with units by directory when no convention matches; a unit above 40 files splits by directory so one worker context holds it.
- **The scanner is the one code seam**: `surfaces` writes the inventory, `--surfaces … --out` scans every file in one run (duplication counts across the platform) and writes the hits grouped by unit to the ledger, printing only a summary, and `hits <file> <unit>` gives a worker its own unit without the duplication hits. Standard library only, no rule changes, so no recalibration.
- **Fan-out through orchestrate**: job `design-audit`, profile `light`, units = surfaces plus `shared`, state dir `.slop-design/`; workers write only their work file, inline when orchestrate is missing. Duplication stays with the main agent as a summary.
- **The ledger is `.slop-design/`**: `STATUS.md`, the inventory with `pending` / `scanned@<sha>` / `skipped:<reason>`, the hits file, `findings.md`, a persistent `keep.tsv`, `plan.md` and, without a tracker, `issues/`. Same roles as ai-slop-audit's ledger; the formats are this skill's own, because per-skill installs cannot share files (ADR 0008).
- **The audit judges; sweep reuses the verdicts** from the persistent keep file. `designscan.py verdict` (the calibration log) runs only in sweep, because it needs a before and an after.
- **Screenshots on a sample**: the browser question is asked once, as today; the sample is drawn from route surfaces only, one per category plus the five with the most hits once duplication hits are left out, and the rest are reported as render not checked.
- **Copy read-only**: the audit runs ai-slop-prose's scanner script (`scripts/scan.py --json`) from where it is installed, in JSON mode only; rewrites stay with sweep's hand-off.
- **Frontend duplication belongs to the design audit**: ai-slop-audit marks a `repeated-class-string`, `duplicate-css-block` or `untokened-colour` group `handoff:ai-slop-design` when `.slop-design/findings.md` exists and every file of the group is in `.slop-design/surfaces.json`, a one-way edge in ADR 0012's call graph; a group with a file outside the design inventory stays the code audit's, since no design finding covers it.
- **Three kinds of batch**, planned in this order: token/component (sequenced expand → migrate per group of surfaces → contract), surface, handoff; each lists files, findings, depends-on and checks.
- **Publish follows ai-slop-audit's publish**: integrated tracker, `gh` or local files; numbered drafts approved with options; a map issue; a marker per batch. With the mattpocock skills installed the report names `/to-tickets` and `/to-spec`, which stay user-invoked; their formats and reserved paths stay theirs (ADR 0005).
- **Only sweep edits**: it takes a batch (`sweep B<n>`), marks its findings `fixed` and never writes the tracker, except on the local route, where it sets the batch's issue file to `State: done` because no pull request closes a file (craft on a handoff batch does the same); a plain sweep above 5 surfaces or 40 frontend files asks first whether to audit. Craft gains `craft <surface>`, a restyle away from the named lane.
- **No `verify` mode**: re-running `audit` reconciles the ledger against a fresh scan.

## Considered options

- Running ai-slop-audit's audit over the frontend: rejected; its categories are about reach and removal, not reflexes, and it would need this skill's catalogue, category frames and browser checks anyway.
- One unit per file, as sweep does: rejected; a hit is judged against the page it renders on, and a platform has too many files for one checkpoint each to stay cheap.
- Putting every component in the surfaces that import it: rejected; a shared button would be judged and counted once per route.
- Screenshots of every surface: rejected; three widths per route does not fit a session on a platform, and a sample with an honest "render not checked" list claims no more than was checked.
- A separate `verify` mode: rejected; a re-run audit already compares a fresh scan with the ledger.

## Consequences

- AUDIT.md, PLAN.md and PUBLISH.md are model-run prose; the deterministic parts live in the scanner and are tested through its CLI with three mini-platforms in `tests/fixtures/design/platforms/`.
- The inventory's import reading is static: aliases beyond `@/`, `~/`, `~~/`, `@@/` and `$lib/` are not resolved, and the files they reach land in `shared`. That costs precision on placement, never coverage.
- The reconcile (`designscan.py reconcile`) matches a finding to the fresh hits by rule, exact match and the file in `Where:`, not by line, so a hit that only moved stays the same finding; a duplication group is matched by rule and match alone, open while any copy is left. Judgment and copy finds have no pattern to match, so the reconcile leaves them `unchecked` and only a fresh read closes them. `--write` updates statuses, lines and the `Scanned:` commit in `findings.md` itself, so a ledger with hundreds of findings is not edited by hand.
- `plan` adds no scanner command: it reuses the platform rescan and `reconcile --write`, then rereads only the judgment, copy and lane findings whose files changed since their `Scanned:` commit, and marks `stale` those that no longer reproduce. A lane is recorded as a finding (`Hit: lane · <lane>`) so a handoff batch closes something, and every other finding on that surface rides in the same handoff batch, because the restyle's sweep would undo a patch made first.
- A migrate or contract batch's files still hold later batches' findings, so its rescan check is the platform reconcile (no copy of the group left in its files, or the group `fixed`) instead of a plain rescan that exits 0. Migrate batches stop at 5 surfaces or 40 frontend files, the size above which a plain sweep asks to audit first.
- `plan.md`'s batch block (`## B<n> · <kind> · <title>`, then one `Key: value` field per line) is the contract with `sweep B<n>`, `craft <surface>` and `publish`; batch IDs are never reused, so a published issue's marker keeps pointing at the same batch after a re-plan.
- `sweep B<n>` reads one batch block of `plan.md` and runs the ordinary sweep steps on its `Files:` with `.slop-design/keep.tsv` as the keep file, so the audit's verdicts are reused and only hits no finding or keep line covers are judged. Once the batch's own checks pass it sets the batch's findings `fixed` and its `Status: done`; a later audit's reconcile confirms or reopens them. It never writes to the tracker, so tracker writes stay in publish.
- A handoff batch is worked by `craft <surface>`, not by sweep, so craft's Record step closes it: after the restyle of the last of its `Surfaces:` passes its checks, the batch's findings become `fixed` and its `Status: done`. An earlier surface leaves it `planned`, because the lane is left only when every page of it is restyled. Craft writes no tracker either.
- The threshold for a plain sweep needs the size of the repo without its inventory in context, so `surfaces --out` prints one line (surfaces, shared units, frontend files, framework). Above 5 surfaces or 40 frontend files the sweep asks with options, audit first recommended; at or below it the sweep runs as before.
- PUBLISH.md takes ai-slop-audit's publish as its model and shares no file with it: the route (integrated through `docs/agents/issue-tracker.md`, `gh`, or `.slop-design/issues/`), the sync of closed issues before drafting, the approval of numbered drafts before anything is written, the map issue first and the marker search among open and closed issues before every create. Its template and markers (`<!-- ai-slop-design batch <B> · … -->`, `<!-- ai-slop-design map -->`) are its own, so neither skill's re-run can mistake the other's issues for its own. Without a tracker each issue is a file whose path stands for its number (`sweep .slop-design/issues/map.md` for `sweep #<map>`), with the same table as ai-slop-audit's local route: its first line, `State: open`, `done` or `wontfix`, is the state the sync reads, and `sweep B<n>` or `craft <surface>` sets `State: done` where a pull request would say `Closes #<n>`.
- Integrated labels follow what an agent can do unattended: `ready-for-agent` only when every finding of a token/component or surface batch is a scanner reflex with a fix direction, and `needs-triage` for every other batch: a handoff batch, where someone chooses a direction first, and a batch with a judgment, copy or lane finding, or one read in uncommitted changes, which someone checks first. Adding the mattpocock tracker adds no edge to ADR 0012's call graph: publish reads their configuration and names `/to-tickets` and `/to-spec`, and runs neither (ADR 0005).
- A scan records the commit it ran at, so it also records which scanned files differ from it (`dirty` in the inventory and the hits file, staged, unstaged or untracked). A finding read in one of them gets `Scanned: <sha>-dirty`: plan rereads it, publish offers to commit and re-audit first and otherwise prints its location without a permalink, and a reconcile on a clean tree pins it to the commit. A permalink to a commit that does not hold the evidence would point at other code.
- `--surfaces … --out` is a report, not a gate: it exits 0 once the hits file is written, whatever is open, and 2 when a file of the inventory is gone. An audit finds open hits by design, and an exit 1 there showed every audit as a failed command in agent shells and stopped any `&&` after it. The gates stay where a step waits for zero: the file rescan (`designscan.py --keep … <files>` exits 0) and `reconcile` (exit 1 while a finding is open or new).
- `hits <file> <unit>` finds a route unit without its leading slash, and undoes Git Bash's rewrite of an argument that starts with `/` into a Windows path (`/pricing` reaching the script as `C:/Program Files/Git/pricing`), so the worker brief passes `pricing` and works in every shell.
