# publish

Turns planned batches into tickets on the repo's issue tracker, shaped for the mattpocock engineering skills: `/triage` reads their state labels, `/implement #<n>` builds from their Agent Brief, `/code-review` checks against them. Arguments: batch IDs (`B1 B4`), default every `planned` batch without an issue.

The ledger is local to this clone. Each issue body carries everything another agent needs, so the issue stands on its own.

## Steps

1. **Config.** Read `docs/agents/issue-tracker.md` and `docs/agents/triage-labels.md`. They should have been provided to you; tell the user to run `/setup-matt-pocock-skills` if not, then stop. Follow the tracker doc for every operation and its target-repo check.
2. **Sync.** For batches already carrying an issue, read its state: closed as completed → findings `fixed`; closed as not planned → `rejected:wontfix (#<n>)`; label `wontfix` likewise. Report the changes.
3. **Draft** one ticket per selected batch using the template below, plus one **map** issue per audit (`AI slop audit @<sha>`: coverage line, finding counts, batch list) when none exists. State label: `ready-for-agent` when every finding is `high` and the batch has a protecting check; otherwise `needs-triage`. Category: `enhancement`.
4. **Quiz.** Show the numbered drafts: title, state label, blocked by. Iterate until the user approves.
5. **Publish** the map first, then batches in dependency order, blockers first. Each batch becomes a sub-issue of the map, with plan `depends-on` as native blocking edges. Before each create, search open issues for the batch's marker; reuse a match instead of filing a duplicate.
6. **Record** `issue: #<n>` on each batch in `plan.md` and the map number in `STATUS.md`.

**Completion.** Every selected batch has exactly one issue (its marker matches one result), every `depends-on` edge exists on the tracker, and `plan.md` records every number.

## Ticket template

Use symbols and behaviour in the brief, since paths go stale. Locations go in the evidence block as permalinks pinned to the scanned commit (`https://github.com/<owner>/<repo>/blob/<sha>/<path>#L40-L58`), which stay valid.

```markdown
> *This was generated by AI during ai-slop-audit.*

## Agent Brief

**Category:** enhancement
**Summary:** <one line, project glossary vocabulary>

**Current behavior:** what the code does now, by symbol.
**Desired behavior:** observable behaviour unchanged; the structure after the change.

**Key interfaces:** symbols touched; public surface unchanged unless stated.

**Acceptance criteria:**
- [ ] <per finding: e.g. zero references to `getJson` remain>
- [ ] <each check command> no worse than baseline `<sha>`: <baseline result>
- [ ] No dependency added; every removed test cites the test that still asserts its behaviour
- [ ] Guards at trust boundaries unchanged

**Out of scope:** anything beyond findings <IDs>; new findings go to a new issue.

<details><summary>Evidence (pinned to <sha>)</summary>

<finding blocks, locations as permalinks>

</details>

<!-- ai-slop-audit: <batch ID> <finding IDs> -->
```
