# Audit

Find every catalogued reflex across a whole platform and judge it, without changing a source file. The ledger in `.slop-design/` (SKILL.md, Ledger) holds the result, so a later run resumes and sweep reuses the verdicts.

Read `REFLEXES.md` and `CATEGORIES.md` (in this folder) in full before step 4. Source files are read, never written: the only files this mode writes are in `.slop-design/`.

1. **Ledger**: create `.slop-design/` when missing (SKILL.md, Ledger). When `STATUS.md` and `inventory.md` exist, this is a re-run, after an interruption or after fixes: units already `scanned@<sha>` are not judged again, an orchestrate job `design-audit` with an open STOPPED block continues from it, and step 4 reconciles the findings with the code as it is now. There is no separate verify mode: running `audit` again is the check.
2. **Inventory**: `designscan.py surfaces [path] --out .slop-design/surfaces.json`. It detects the framework from `package.json` (Next.js, Nuxt, SvelteKit, Astro, react-router) and lists the **surfaces**: each route with the files only it reaches, plus the `shared` unit (files reached by several routes, and in `unreached` those reached by none). With no route convention it falls back to units by directory. In a monorepo whose root has no framework, run it per app (`apps/web`, `apps/admin`). Write `inventory.md`, one row per unit: `| unit | kind | files | category | status |`, status `pending`; the files column is the count, `surfaces.json` holds the list. On a re-run, rewrite `surfaces.json` and keep each row's status: a unit new to the inventory gets a `pending` row, and a row whose unit is gone becomes `skipped:removed`. Done when every unit has a row.
3. **Context**: read `PRODUCT.md` / `DESIGN.md` when present and the theme or token files (Tailwind config, `@theme`, CSS custom properties). Write in `STATUS.md` one line of what the brand has already committed to: those choices are `chosen: brand`. Name each route unit's category from `CATEGORIES.md` in its row (`shared` takes the category of most routes it serves).
4. **Scan once**: `designscan.py --surfaces .slop-design/surfaces.json --out .slop-design/hits.json --keep .slop-design/keep.tsv` (drop `--keep` while the file does not exist). Every frontend file is scanned in one run, so duplication counts across the platform. Read only the summary it prints (hits and open hits per unit, busiest first, and the duplication groups); `designscan.py hits .slop-design/hits.json` prints it again. Note the `scanned at` commit, and the files the summary lists with uncommitted changes: that commit does not hold what was read in them, so their findings are not pinned to it (step 7). When the list holds files of the units being judged, say so in the report and recommend committing before `publish`.

   **Reconcile** (a re-run with `findings.md`): `designscan.py reconcile .slop-design/findings.md .slop-design/hits.json --keep .slop-design/keep.tsv --write`. It matches each finding to the fresh hits by rule, match and file: `fixed` when the hit is gone, `open` when it is still there (a `fixed` or `stale` finding whose hit is back reopens), `resolved` when a keep line now covers it (status `rejected:kept`); a duplication group stays open while any copy is left. `--write` puts those statuses, the hit's current line and the fresh commit into `findings.md`; `rejected:<reason>` findings keep their status, and judgment and copy finds are `unchecked` (no pattern can tell), left as they are. Read only the summary it prints: the status changes, then the **new** hits, the ones no finding or keep line covers. New hits in a `pending` unit are judged with the rest of the unit in step 5; new hits in a unit already `scanned@<sha>` are judged on their own, with the unit brief and those hits in place of the `hits` command, inline or as one more orchestrate unit, and their unit's row moves to the fresh commit in step 7. Nothing else in a scanned unit is judged again.
5. **Judge by surface**: run the `orchestrate` skill when installed: job `design-audit`, profile `light`, state dir `.slop-design/`, units = the `pending` rows of `inventory.md` in order, done when every hit of the unit has a verdict and the judgment-only list was read. Workers write only their work file. Without orchestrate, work the units in sequence yourself, writing the same checkpoints. In the brief, `<unit name>` is the unit as `inventory.md` names it, without a route's leading slash (`pricing` for `/pricing`, `blog/[slug]` for `/blog/[slug]`; the root route stays `/`): Git Bash rewrites an argument that starts with `/` into a Windows path, and the scanner finds the unit either way. Unit brief:

   > Audit one unit of a platform, read-only: never edit a source file. Read `<skill dir>/REFLEXES.md` and the `<category>` section of `<skill dir>/CATEGORIES.md`. The brand has committed to: `<brand line>`. Run `python <skill dir>/scripts/designscan.py hits .slop-design/hits.json "<unit name>"` for this unit's hits (duplication hits are left out: they are the caller's), and read the unit's files. Give each hit one verdict: `reflex`, `chosen` with a reason (`brief`, `brand`, `sequence`, `content`, `a11y`, `handoff`) or `fp`, per SKILL.md's Verdicts; a hit that breaks the category's frame or floor is a reflex even when it looks deliberate. When most hits point at one lane (REFLEXES.md, Lanes), keep them with reason `handoff` and name the lane. Then read REFLEXES.md's judgment-only list and the category's reflexes against the unit's files, one item at a time. Copy: with ai-slop-prose installed, run `python <prose skill dir>/scripts/scan.py --json <files>` (`${CLAUDE_SKILL_DIR}/../ai-slop-prose/` when the set is installed together) (it reads visible strings only, and you rewrite nothing) and count its hits; otherwise list the visible strings that read as copy reflexes (buzzwords, "Get started" next to "Learn more", invented testimonials). Write: one line per reflex, `<file>:<line> · <rule> · <match exactly as printed> · <one-line fix direction>`; one keep line per kept or `fp` hit, `<rule><TAB><match><TAB><reason>`; the judgment-only finds with file and line; the copy count and strings; the lane, if any.

6. **Duplication**: the summary's duplication groups stay with you. Judge each group once: a reflex when one component, class or token should replace the copies; `chosen` when the repetition is deliberate (a token file, generated styles). Each reflex group is one finding naming every file.
7. **Merge**: from each work file, in unit order, append the findings to `findings.md` (schema in SKILL.md, Ledger) with the next free IDs, the keep lines to `keep.tsv` (skip lines already there), and set the unit's row to `scanned@<commit>`. A finding whose `Where:` names a file the scan listed with uncommitted changes gets `Scanned: <sha>-dirty`, so no permalink is pinned to a commit that does not hold it; a later reconcile on a clean tree replaces it with the commit. A lane the worker named becomes one finding on its unit, category `lane`, `Hit: lane · <lane>` with the lane as REFLEXES.md names it and `Where:` the unit's entry files, so `plan` can give the unit a handoff batch. On a re-run, the same `reconcile` command lists no new hit once every judged one is in `findings.md` or `keep.tsv`. A unit whose worker failed stays `pending` and is named in the report. Then record the audit's judgments: `designscan.py verdict --judged .slop-design/findings.md --keep .slop-design/keep.tsv`. Each scanner finding and keep line becomes one verdict, once across re-runs; the lines it prints say how many verdicts each rule has toward the 30 that let the user's verdicts move its tier (ADR 0018).
8. **Render a sample**: ask with options once whether to open a browser (SKILL.md, browser tool) unless the user already answered this session. The sample is drawn from the route surfaces only (never `shared`, a directory unit or a `skipped:<reason>` row, none of which is one page to open): one route per category in `inventory.md`, plus the five routes with the most hits once the duplication hits are left out (they are counted across the platform, not on the page). In the directory fallback there is no route to open, so every unit is reported as render not checked. With the user's yes, open each sampled surface in the running app or a local build, take screenshots at 390, 768 and 1440 pixels wide, check at each width that `document.documentElement.scrollWidth` does not exceed `clientWidth`, and judge them against REFLEXES.md's judgment-only list and DIRECTION.md's responsive checks; what they show becomes findings on that surface. Every other surface, or all of them without a browser, is reported as render not checked.
9. **Report**: write `.slop-design/report.md` and show it. The first line is `COMPLETE: N/N surfaces` when every row is `scanned@<sha>` or `skipped:<reason>`, otherwise `PARTIAL: k/N surfaces` followed by the pending units. On a re-run, the next line counts what the reconcile changed: fixed, reopened, kept since and new findings. Then one line per REFLEXES.md category (hits, reflex, chosen with reasons, fp; zeros included), the judgment-only line (finds by surface), the copy line (copy hits per surface, or the strings listed without ai-slop-prose), the handoffs with their lane, the surfaces whose render was checked and those whose render was not checked, the busiest surfaces, and the progress lines `verdict --judged` printed, with the audit command they suggest. Rewrite `STATUS.md`.

**Completion.** No source file changed (`git status --short` shows what it showed before the run); every row of `inventory.md` is `scanned@<sha>` or `skipped:<reason>`, or the report says `PARTIAL`; every hit in `hits.json` has a finding or a keep line (on a re-run, `reconcile` lists no new hit); and the report has all nine category lines, the judgment-only line, the copy line and the render-not-checked list.
