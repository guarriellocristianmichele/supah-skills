# Sweep

Find every catalogued reflex in the files, give each hit a verdict, fix the reflexes, and read for the ones no pattern sees.

Read `REFLEXES.md` (in this folder) in full before step 3.

## Batch

`sweep B<n>` works one batch of `.slop-design/plan.md` (PLAN.md, plan.md format), so fixing follows the plan. The steps below run as for files, with these changes:

- **Load**: read the batch's block only. Its `Status:` must be `planned` and every batch in its `Depends-on:` `done`; when one is not, name it and ask with options: work that batch first (recommended) or stop. A handoff batch is worked by its `Work:` line, `craft <surface>`: name the command and stop.
- **Scope** (step 1): the batch's `Files:`, nothing else, and no threshold question. A fix that needs a file outside them is not made: the report lists it for a re-plan.
- **Keep file**: `.slop-design/keep.tsv`, the ledger's persistent one, in place of a scratchpad file. Every scan and rescan passes `--keep .slop-design/keep.tsv`, so the hits the audit kept or marked `fp` are resolved and not judged again. Workers fanned out in step 3 keep their own keep files, appended to it after the merge.
- **Judge** (step 4): a hit that a finding in the batch's `Findings:` or `Serves:` names already has its verdict, `reflex`, and is fixed by the finding's `Fix:` line. Only hits that no finding and no keep line covers are judged, and the kept ones are appended to `.slop-design/keep.tsv` with their reason. A hit that belongs to another batch's finding is left for that batch.
- **Read and copy** (steps 6 and 7): the batch's judgment-only and copy findings are fixed as written, and the read and the screenshots cover the batch's `Surfaces:`.
- **Rescan** (step 8): the batch's `Checks:` lines as written: its rescan (for a migrate or contract batch, the platform rescan and the reconcile it names), the content check against the step 1 snapshots, and the render check.
- **Ledger** (step 11) closes the batch.

## Steps

1. **Scope**: the files in the arguments, or `git ls-files` filtered to `.html .htm .css .scss .less .js .jsx .ts .tsx .mjs .vue .svelte .astro`, minus vendored, generated, minified and `node_modules` files; `B<n>` scopes to that batch (Batch). With no argument, first run `designscan.py surfaces --out <scratchpad>/surfaces.json` and read only the line it prints. When the repo is above 5 surfaces or 40 frontend files, ask with options: audit first (recommended: `/ai-slop-design audit` reads the whole platform without editing, then `plan` and `sweep B<n>` fix it one batch at a time), sweep everything (every file, fanned out as in step 3), or sweep one path (the user names a folder or route, and the scope is its files). At or below the threshold the sweep takes every file without asking. Snapshot each file to the scratchpad as `<name>.orig`.
2. **Context**: read `PRODUCT.md` / `DESIGN.md` when present, the theme or token files (Tailwind config, `@theme`, CSS custom properties) and the page the files render. Write down in one line what the brand has already committed to: those choices are `chosen: brand`. Name the category of each surface in `CATEGORIES.md` and read its section: a hit that breaks the category's frame or floor is fixed even when it looks deliberate, and the judgment-only read in step 6 includes the category's reflexes.
3. **Scan**: `designscan.py --json <files>`, all files in one call so duplication is counted across them. Each hit carries `line`, `rule`, `category`, `tier`, `match` and `context`.
   More than 3 files: run the `orchestrate` skill when installed, job `design-sweep`, profile `light`, units = files, unit brief = steps 4, 5 and 8 for one file with that file's hits from this scan (duplication hits excluded), and each worker may edit its own file and its own keep file. Duplication hits stay with you: after the merge, fix them across files (one component, class or token), then go on from step 6 for the whole set, steps 8 and 9 included. Without orchestrate, work the files in sequence.
4. **Judge** each hit in its context with one verdict (SKILL.md). Kept and `fp` hits go into the keep file with their reason.
5. **Fix** the reflexes category by category, in REFLEXES.md order, with the fix direction under each rule. Content, behaviour and accessibility stay as they were; a fix changes how the page looks, never what it says or does. When most hits on a page point at one lane (REFLEXES.md, judgment-only section), patching each hit leaves the lane in place: keep those hits with reason `handoff` and name the lane in the report, so `craft <surface>` can give the page a new direction.
6. **Read for what the scanner cannot see**: REFLEXES.md's judgment-only list, one item at a time, against the page as a whole. Ask with options to open a browser (SKILL.md, browser tool) unless the user already answered this session; with the user's yes, open the running page or a local build and take screenshots at 390, 768 and 1440 pixels wide and judge them against the same list and DIRECTION.md's responsive checks; at each width, check in the page that `document.documentElement.scrollWidth` does not exceed `clientWidth` (no horizontal scroll). Record what each width showed.
7. **Copy**: with ai-slop-prose installed, run its sweep on the same files; otherwise list the visible strings that read as copy reflexes (buzzwords, "Get started" next to "Learn more", invented testimonials).
8. **Rescan**: `designscan.py --keep <keep file> <files>` exits 0. A new hit means a fix brought in another reflex: fix it and rescan.
9. **Record**: one call for the whole sweep, every snapshot paired with its file: `designscan.py verdict <scratchpad>/<name>.orig <file> [<scratchpad>/<name>.orig <file>…] --keep <keep file>` (for a batch, `--keep .slop-design/keep.tsv`), so duplication is judged across the files as step 3 saw them. Only sweep writes this log, because it needs a before and an after; audit and plan never do. The log is evidence for whoever maintains the tiers; it never changes a tier by itself.
10. **Report**: one line per REFLEXES.md category (hits, fixed, chosen with reasons, fp, model-only finds; zeros included), the handoffs with their lane and the command that works each one (`/ai-slop-design craft <surface>`), what the screenshots showed or that no browser was available, and the diff against the snapshots. A batch's report also names the batch, the findings it closed and its `Issue:` line.
11. **Ledger** (`sweep B<n>` only), once the batch's checks pass (its rescan exits 0, or for a migrate or contract batch the reconcile shows what its rescan line asks): set every ID in its `Findings:` to `fixed` in `findings.md`, set the batch's `Status: done` in `plan.md` (an expand or migrate batch, whose `Findings:` is `none`, is done when its checks pass), and rewrite `STATUS.md`: finding counts and the next action, the next `planned` batch whose `Depends-on:` are all `done`. A later `audit` reconciles these statuses with a fresh scan. Sweep never writes to the tracker: no `gh` call, nothing in `.slop-design/issues/`, the `Issue:` line as it was; the issue is closed by the user or synced by `/ai-slop-design publish`.

**Completion.** The rescan exits 0, verdicts are recorded for every file, the report has all nine category lines plus the judgment-only line, and the screenshots were judged or reported unavailable. A batch's sweep also leaves its findings `fixed` in `findings.md`, its `Status: done` in `plan.md` and the tracker untouched.
