# Compare

Show two offers, names or positionings to two halves of the panel balanced by segment, each buyer seeing one, and report how each converts with the panel's noise next to the difference. `P` is the panel folder, `.buyer-panel/<slug>/`; `panel.py` is `python "${CLAUDE_SKILL_DIR}/scripts/panel.py"`.

Read `RECORDS.md` before step 1, `INTERVIEW.md` before step 2, `SCORING.md` before step 5 and `READING.md` and `CRITIQUE.md` before step 7 (all in this folder). Bold steps without a number (**Base round**, **Checks**, **Critique**, **Sweep**) are in SKILL.md, steps the modes share.

1. **Base round.** The **Base round**; its `round.json` is the template for both halves: price, currency, options, model, interviews and batch size. The two rounds are `r<k+1>-A` and `r<k+1>-B`. Done when the base summary exists and the two labels are known.
2. **Variants.** The text after `compare` names A and B: two offers, two product names or two positionings. Missing or unclear: ask for them, one question each. Write each as the offer card's words (INTERVIEW.md, the cards): the same shape, about the same length, the same price unless the user compares two prices, nothing styled to win and no word that marks one as the new or improved one. The order the user named them in is A, then B. Show both cards and ask with options: **compare these** (recommended), **change A**, **change B**, **stop**. Done when the user chose to compare.
3. **Split.** Create `P/rounds/r<k+1>-A/` and `P/rounds/r<k+1>-B/`, each with a `round.json` that copies the base round's and changes `label`, `offer` (and `price` when the variant sets one), and adds `variant` (`A` or `B`) and `compare` (the other round's label). Then `panel.py split --buyers P/buyers.jsonl --options <ids> --batch-size <n> --out-a P/rounds/r<k+1>-A/cards.jsonl --out-b P/rounds/r<k+1>-B/cards.jsonl`: it halves every segment, sends a segment's odd buyer to A, then B, in turn, and deals each half's cards as `deal` does. Copy its `seed` into both `round.json` files and show its segments line. Done when both `round.json` files validate and every buyer has exactly one card across the two files.
4. **Interviews.** Each buyer sees one variant, in a fresh context that sees no other variant and no earlier round. Run the `orchestrate` skill when installed: job `buyer-panel-<slug>-<k+1>-compare`, profile `light`, state dir `P/rounds/`, units = each half's batches in its `cards.jsonl` (a unit never holds both variants), unit brief = INTERVIEW.md's worker brief with that round's cards, each worker writing only `P/rounds/<label>/answers/batch-<n>.jsonl`. Without orchestrate, interview one buyer at a time as RUN.md step 9 says, with `interviews: inline` in both rounds; this context then saw both variants, and the report says independence was partial. Done when `panel.py validate` exits 0 on every answers file and every buyer has an answer in their own half.
5. **Judge.** Judge each half apart (RUN.md step 10, one judge context per round), so no judge reads both variants' reactions. Then `panel.py aggregate` each round with `--out summary.json`; its `Missing` line lists the other half, which never saw this variant: that is expected, and `compare` names the buyers who are really missing. Then the **Checks** on each round: each half is a round shown to its half of the panel, so a failed check is not advisory. Done when both rounds have `summary.json` and `checks.json`.
6. **Compare.** `panel.py compare P/rounds/r<k+1>-A P/rounds/r<k+1>-B --out P/rounds/r<k+1>-A/compare.json`, then once more without `--json` for the Markdown. A buyer in both rounds exits 2: one context saw both variants, so re-deal and re-interview. A `Missing in` line names buyers dealt a card with no scored answer: interview or judge them, then run it again. Done when it exits 0 and prints no `Missing in` line.
7. **Report.** The **Critique**, reading both halves' `summary.json` and `checks.json`, written to `P/rounds/r<k+1>-A/critique.md`. Then write `P/rounds/r<k+1>-A/report.md` per READING.md, its Checks section holding each half's, A first, with these sections between the summary and the verdict: **The variants** (both cards as the buyers read them); **Side by side** (`compare`'s Markdown, unchanged: BUY share on each side, B minus A, the noise, the segments, reasons and choices per side); **Buyers** (each round's buyer table from `aggregate`, A first). Noise is shown, not tested: set the difference next to the standard error and the one-buyer swing in words ("B minus A is 4 points; one buyer moves the smaller half 6"), and never write "A wins", "B wins" or that a difference is significant. A difference smaller than the one-buyer swing means the panel cannot tell the variants apart; a larger one is still a hypothesis from synthetic buyers. A segments line that says not balanced goes into the report as a reason to read the difference with care. Reasons per side say what each variant made buyers think about; quote buyers from the tables by id. A failed check on either half makes the verdict that half's `Do not trust this round` line: the comparison cannot be read. Otherwise the verdict names the variant to take to a real test, or both when the panel cannot tell them apart, and the first real test splits real visitors between the two (two smoke-test pages, or the two versions of one ad) with the threshold written first.
8. **Sweep.** The **Sweep** on `report.md`.
9. **History.** Append one line per round to `P/history.md`, A first: date, label, `compare` and the other label, offer, price, raw and discounted BUY share over its half, and for A the difference, the noise and the verdict.

**Completion.** Both rounds validate and aggregate with exit 0; every buyer of the panel was dealt one variant, and no buyer answered both; each half was judged in its own context and has its `checks.json`; `compare.json`, `critique.md` and the report exist in `r<k+1>-A`; the report opens with the simulated-panel line, shows both halves' Checks sections and the devil's advocate, shows `compare`'s numbers and noise unchanged, sets the difference beside the noise without testing it or naming a winner, and ends with a verdict and one real test; the history has a line for each round.
