# Run

Build a panel for one idea and run its first round, from brief to report. `P` below is the panel folder, `.buyer-panel/<slug>/`; `panel.py` is `python "${CLAUDE_SKILL_DIR}/scripts/panel.py"`.

Read `RECORDS.md` before step 2, `BUYERS.md` before step 7, `INTERVIEW.md` before step 9, `SCORING.md` before step 10 and `READING.md` and `CRITIQUE.md` before step 12 (all in this folder).

1. **Panel.** With an idea in `$ARGUMENTS`, slug it and look for `P`. When `P` already exists, ask with options: start a new round on the same buyers (go to step 8 with the next label), rebuild the panel from scratch (move the old folder to `P-<date>`), or stop. Done when `P` is new or the user chose.
2. **Brief.** With an idea, take it as the one-line idea and infer audience, price and alternatives from it, marking every guess. Without one, read the project: `README*`, `PRODUCT.md`, `DESIGN.md` (root, `docs/`, `.agents/context/`), pricing pages and landing copy (search for `pricing`, `price`, `plan`, currency symbols), and draft the same four fields from what it says. Show the brief and ask with options: **use it**, **change the audience**, **change the price**, **change the alternatives**; apply a change and ask again. Write `P/brief.json`; done when `panel.py validate P/brief.json` exits 0 and the user chose "use it".
3. **Research.** Before inventing any buyer: search the web for the competitors and substitutes this audience uses, each one's current price and plan, and what the audience spends in the category (surveys, industry reports, public pricing of the tools they already pay for). To open pricing pages, ask the browser question first (SKILL.md, browser tool). Write `P/research.md`: one line per fact with its source URL and the date seen; mark any figure you could not find as unknown, never estimate it silently. Update `brief.json`'s alternatives with real names and prices. Done when every alternative has a price with a source and category spend has a source or is marked unknown.
4. **Ledger.** First panel in this project: ask the ledger question (SKILL.md, panel ledger) and apply the answer.
5. **Size.** Ask with options: **100 buyers** (recommended: enough for reasons to repeat), **30 buyers** (cheaper, reasons only), **200 buyers** (more detail per buyer type, about twice the cost of 100).
6. **Plan.** From the research, write `P/plan.json`: segments of the audience with the share of the panel each takes and the budget range each spends in the category, each segment with the source line in `research.md` it rests on. Done when `panel.py validate P/plan.json` exits 0.
7. **Buyers.** Write `P/buyers.jsonl` per BUYERS.md, segment by segment, to the plan's shares. Done when `panel.py validate P/buyers.jsonl` exits 0 (it checks every field and each buyer against the plan); fix the lines it names and run it again.
8. **Round.** Create `P/rounds/<label>/` (`r1` for the first round) and its `round.json`: the offer as it reads on the card (INTERVIEW.md), the price, the option ids (`offer`, each alternative's name, `nothing`), the model writing the buyers (your own model name and version), `interviews` and `batch_size` (5 with orchestrate; `inline` and 1 without). Then `panel.py deal --buyers P/buyers.jsonl --options <ids> --batch-size <n> --out P/rounds/<label>/cards.jsonl` and copy its `seed` into `round.json`. Done when `round.json` validates and `cards.jsonl` holds one line per buyer.
9. **Interviews.** Run the `orchestrate` skill when installed: job `buyer-panel-<slug>-<label>`, profile `light`, state dir `P/rounds/<label>/`, units = the batches in `cards.jsonl`, unit brief = INTERVIEW.md's worker brief for that batch's buyers, done criterion = one valid answer line per buyer of the batch, each worker writing only `P/rounds/<label>/answers/batch-<n>.jsonl`. Without orchestrate, interview the buyers one at a time in `cards.jsonl` order, writing each answer before reading the next buyer, with `interviews: inline` in `round.json`. Done when `panel.py validate` exits 0 on every answers file and every buyer has an answer (re-run only the missing batches).
10. **Judge.** `panel.py reactions P/rounds/<label> --out P/rounds/<label>/judge-input.jsonl`, then hand that file and SCORING.md's judge brief to a subagent (or, without one, judge it yourself reading nothing else). It writes `P/rounds/<label>/scores.jsonl`. Done when `panel.py validate` exits 0 on it.
11. **Numbers.** `panel.py aggregate P/rounds/<label> --out P/rounds/<label>/summary.json`. Exit 3 names the records at fault: re-interview or re-judge those buyers and run it again; never edit an answer or a score to make it pass. Then run it once more without `--json` for the Markdown summary and buyer table. Then `panel.py checks P/rounds/<label> --out P/rounds/<label>/checks.json`, and once more without `--json` for the Checks section; exit 1 means the round is not to be trusted (READING.md, the checks): never edit a record or a threshold to make a check pass.
12. **Critique and report.** Hand CRITIQUE.md's critic brief and the files it lists to a subagent (or, without one, write it yourself reading only those files); it writes `P/rounds/<label>/critique.md`. Then write `P/rounds/<label>/report.md` per READING.md: the simulated-panel line, the summary and buyer table exactly as `aggregate` printed them, the Checks section exactly as `checks` printed it, how the panel was run, the devil's advocate section from `critique.md`, the verdict (`checks`' verdict line when it printed one) and the first real test this week.
13. **Sweep.** With ai-slop-prose installed, run its sweep on `report.md` with purpose `panel report`; it may rewrite the prose, never a number, quote or table row. Without it, the method section says the report was not swept.
14. **History.** Append one line to `P/history.md`: date, label, offer, price, raw and discounted BUY share, the price range, the failed checks or `checks passed`, the verdict.

**Completion.** `brief.json`, `plan.json`, `buyers.jsonl` and every round record validate; `aggregate` exits 0 on the round and `checks.json` holds its checks; `critique.md` exists; `report.md` opens with the simulated-panel line naming the model, holds the summary, full buyer table and Checks section as the script printed them and the devil's advocate section apart from every buyer's words, says "Do not trust this round" in its verdict when a check failed, states the batch size or the partial independence, and ends with a verdict and one real test; `research.md` has a source for every price; the history has the round's line; the ledger question was asked once.
